# Рекурсия в Python

## Вызов функции

Функция - это именованный блок кода, который выполняется при вызове. При вызове `area(3, 4)` значения 3 и 4
попадают в параметры, функция выполняет тело и возвращает результат через `return`. Если `return` не написан,
функция возвращает `None`. Каждый вызов работает со своими локальными переменными: переменная `x` внутри функции
не видна снаружи и не связана с переменной `x` в другом вызове той же функции.

## Стек вызовов

Когда одна функция вызывает другую, Python запоминает, куда вернуться. Для этого есть стек вызовов: при каждом
вызове на вершину стека кладётся кадр (frame) с локальными переменными и местом возврата. Когда функция делает
`return`, её кадр снимается со стека, и выполнение продолжается в функции, кадр которой стал верхним.
Стек работает по принципу LIFO: последним вошёл - первым вышел. Поэтому функция, вызванная последней,
заканчивается первой. Traceback при ошибке - это распечатка стека вызовов в момент ошибки.

## Базовый и рекурсивный случай

Рекурсия - это когда функция вызывает саму себя. Рекурсивная функция состоит из двух частей. Базовый случай -
условие, при котором функция отвечает сразу, без нового вызова себя. Рекурсивный случай - функция сводит задачу
к меньшей такой же задаче и вызывает себя для неё.

```python
def factorial(n):
    if n == 0:          # базовый случай
        return 1
    return n * factorial(n - 1)   # рекурсивный случай
```

Каждый рекурсивный вызов обязан приближать задачу к базовому случаю. Если базовый случай не написан или до него
нельзя дойти (например, `factorial(-1)` уходит в -2, -3...), вызовы не заканчиваются. Частая ошибка новичков -
думать, что рекурсия "сама поймёт", когда остановиться: остановку определяет только базовый случай.
Ещё одна ошибка - считать, что все вызовы factorial делят одну переменную n. На деле у каждого вызова свой кадр
и своя n: factorial(3) ждёт результат factorial(2), тот ждёт factorial(1) и так далее.

## Глубина рекурсии и RecursionError

Каждый рекурсивный вызов добавляет кадр в стек, а память под стек ограничена. Python ограничивает глубину
рекурсии: по умолчанию около 1000 вызовов, узнать лимит можно через `sys.getrecursionlimit()`. При превышении
возникает `RecursionError: maximum recursion depth exceeded`. Обычно это признак ошибки в базовом случае, а не
повод поднимать лимит через `sys.setrecursionlimit`. В Python нет оптимизации хвостовой рекурсии: даже если
рекурсивный вызов стоит последним, кадр всё равно остаётся в стеке. Поэтому обработать рекурсией список из
100 000 элементов не получится, а циклом - легко.

## Мемоизация

Наивное вычисление чисел Фибоначчи `fib(n) = fib(n - 1) + fib(n - 2)` вызывает функцию для одних и тех же
аргументов много раз: fib(5) дважды считает fib(3) и трижды fib(2). Число вызовов растёт экспоненциально, и уже
fib(35) считается секунды. Мемоизация - это запоминание результатов: если функцию уже вызывали с таким аргументом,
ответ берётся из словаря, а не считается заново. В Python для этого есть декоратор `functools.lru_cache`
(или `functools.cache`). С мемоизацией fib(n) делает около n вызовов вместо экспоненты. Цена - память под
сохранённые ответы. Мемоизация не уменьшает глубину рекурсии: fib(5000) упадёт с RecursionError и с кэшем.

## Рекурсия или цикл

Любую рекурсию можно переписать циклом, если хранить незавершённую работу в своём стеке (списке). Рекурсия
удобна, когда данные сами рекурсивны: дерево каталогов, вложенные списки, JSON с вложенными объектами, обход
графа в глубину. Там рекурсивный код короче и ближе к определению задачи. Цикл лучше, когда глубина может быть
большой (из-за лимита рекурсии) или задача линейная, как сумма списка. Рекурсия не быстрее цикла: каждый вызов
функции в Python стоит дороже итерации цикла. Выбор - это вопрос ясности кода и глубины, а не скорости.
